UNDER THE HOOD

HOW IT
WORKS.

BeatMyScroll looks intentionally chaotic, but the game underneath is simple. Browser input is converted into a normalized scroll rate, that rate drives the speed display and score multiplier, and the run ends when meaningful input disappears for roughly 1.5 seconds.

01

WHAT COUNTS AS A SCROLL?

Browsers do not give every device the same kind of input. A traditional mouse wheel can emit wheel events in discrete steps. A high-resolution wheel or trackpad can emit many smaller deltas. A phone reports touch movement rather than wheel movement at all.

BeatMyScroll therefore does not simply count browser events. It takes the magnitude of meaningful wheel or touch movement and converts that input into a common internal distance. That internal distance is what feeds the game's speed calculation.

Important: “scrolls/s” is a BeatMyScroll gameplay unit. It is useful for comparing runs inside BeatMyScroll, but it is not a scientific measurement of physical mouse-wheel notches per second.

Why dragging the scrollbar is different

The game listens to actual wheel/touch gameplay input instead of awarding points based on the document's page position. Jumping a browser scrollbar to the bottom therefore does not create the same score as sustained input. This is also why the active game screen itself does not need an infinitely tall web document to create the illusion of an endless run.

02

LIVE SPEED VS. SCORING SPEED

BeatMyScroll intentionally separates the number you see from the number used to keep scoring stable. The live speed display is uncapped: if the browser reports an enormous burst, the max-speed stat can preserve that burst.

The scoring path uses a normalized rate so unusual hardware or a single giant browser delta cannot make the score explode without limit. This lets the speed stat stay fun and uncapped while the raw-score leaderboard remains more comparable between devices.

Why speed decays

The live rate fades continuously when input slows. This makes acceleration and deceleration visible instead of letting one fast flick leave the HUD stuck at a high speed. The same fading rate drives visual intensity: speed lines stretch, the projected corridor becomes more aggressive, and higher arcade ranks become increasingly unstable.

03

THE SCORE

The raw score is based on input distance multiplied by a speed-dependent scoring multiplier and any active RUSH multiplier. In plain English: more scrolling scores points, faster scrolling makes those points worth more, and a completed RUSH gate can temporarily multiply them.

This means two runs with the same total input can finish with different scores. The player who maintains a stronger pace and successfully uses RUSH windows can score more from that input.

Why there are three leaderboards

  • Raw score rewards the overall run: pace, survival and multiplier management.
  • Average speed rewards sustained intensity across active scrolling time.
  • Maximum speed records the fastest burst observed during the run.

Keeping these categories separate avoids pretending that one number describes every kind of skill.

04

THE 1.5-SECOND RULE

The core pressure mechanic is the inactivity timer. Every meaningful input refreshes the run. Once the game has gone roughly 1.5 seconds without meaningful scrolling, the run ends.

The danger bar is a direct visualization of that deadline. In the final portion it turns red and the interface enters a panic state. Recovering from that state before the deadline creates a CLUTCH SAVE callout, but it does not secretly add score; it is feedback for a recovery the player already made.

05

RUSH GATES & COMBOS

RUSH gates are short optional challenges that ask for a fixed amount of downward input inside a limited window. Lower multipliers are deliberately easier to complete. Larger rewards demand more input in less time.

Completing a gate activates its multiplier for a limited period. Missing the gate resets the active RUSH multiplier and breaks the current RUSH chain. The chain itself is mostly an arcade-feedback system; its milestone callouts do not silently change the leaderboard rules.

Why the gate is three-dimensional

Earlier prototypes used glowing circles. They were readable but visually disconnected from the speed fantasy. The current gate is staged inside a projected corridor so it feels like a checkpoint approaching the player rather than a flat UI popup.

06

RANKS, ZONES & VISUAL STAGES

D through SSS ranks are live feedback for current speed. They do not replace the leaderboard stats. Higher ranks shake and distort more to make speed feel unstable and earned.

Zones are score milestones that change the atmosphere of the run. Separately, sustained high-speed stages can trigger larger audio/visual moments. Those systems deliberately sit on top of the same underlying score rather than creating separate hidden currencies.

PB Ghost

When you set a personal best, BeatMyScroll stores a lightweight timeline of that best run in your browser. Future runs can compare the current score with that old score at the same elapsed time. The PB Ghost is local to your browser; it is not another public leaderboard record.

Overdrive

OVERDRIVE is a separate arcade objective for sustained speed. Holding roughly 18+ scrolls/s charges the meter; maintaining faster pace fills it more quickly. When it reaches 100%, the game enters a short visual Overdrive state. It deliberately does not multiply score, so older leaderboard results remain comparable.

Daily Challenge

Each UTC day generates one deterministic objective—score, endurance, sustained average speed or burst speed. Completion and the daily streak are stored locally in the browser and do not alter the global leaderboard.

07

PERFORMANCE MODE

The game automatically reduces decorative rendering when a device reports limited hardware or when frame timing shows that the full effect stack is struggling. Lite Mode uses fewer tunnel elements, fewer projected particles, simpler shadows and fewer expensive animations.

The important part is what Lite Mode does not change: scoring, inactivity timing, speed thresholds, leaderboard values and RUSH difficulty remain gameplay systems rather than graphics settings.
